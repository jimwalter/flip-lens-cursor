# AGENTS.md

## Cursor Cloud specific instructions

- **Working agreement (owner preference):** log progress to GitHub for transparency — commit often with clear messages, and treat each working feature as a checkpoint (small PR merged per checkpoint, or committed directly to `main` if the owner has opted into that). Business north star: a low-maintenance, self-serve product (users discover, convert, and pay on their own) that "just works" with minimal supervision — target dependency updates roughly monthly or less. Prefer designs that reduce ongoing operational babysitting (e.g. remote-configurable scraper selectors, graceful degradation, managed auth/billing) over ones that need frequent hand-patching.

- **What this is:** `flip-lens-cursor` is a Chrome **Manifest V3** extension (**FlipLens**) living entirely in `extension/`. See `README.md` for the user flow and `PRODUCT_SPEC.md` for the spec.
- **No build, no dependencies:** there is no package manager, bundler, or lockfile. The source in `extension/` loads directly. There is nothing to install and no update/build step to run.
- **Load & test (manual):** at `chrome://extensions` enable Developer mode → **Load unpacked** → select `/workspace/extension`. Trigger via the toolbar icon or `Ctrl+Shift+Y` (`Cmd+Shift+Y` on macOS). After editing files, click the reload (↻) icon on the FlipLens card to pick up changes.
- **Commercial seams (`extension/src/`):** `config.js` (env/flags/plans — `env=development` unlocks everything so no account is needed), `auth.js` (local anonymous session; hosted auth stubbed), `entitlements.js` (single gate — `resolveEntitlements()`/`can()`), `api.js` (backend client; no-op locally), `history-store.js` (history repo, enforces plan cap), `analytics.js` (opt-in no-op), `settings.js`. UIs never check plans or hit the network directly — they message the worker (`FLIPLENS_GET_STATE`, `FLIPLENS_SET_SETTINGS`, history `FLIPLENS_*`). The service worker is an **ES module** (`"type": "module"`), so it can `import` from `src/`; content scripts and the panel/options stay classic and talk via messages. See `ARCHITECTURE.md`.
- **Plan simulator:** Settings (options page) → "Simulate plan" (dev only) previews Free/Pro gating (history cap, export) without billing.
- **Architecture:** `background.js` (service worker) routes the trigger, calls `chrome.tabs.captureVisibleTab`, and crops the region with `OffscreenCanvas` scaled by `devicePixelRatio`; `overlay.js`/`overlay.css` is the injected drag-to-select UI; the full cropped image is passed in-memory via `chrome.storage.session` (keyed `img_<captureId>`) to `uploader.html`/`uploader.js`. `background.js` also owns the search history (`chrome.storage.local`, key `flip_history`) and a tabId→captureId map (`chrome.storage.session`, key `flip_pending`).
- **Sidebar:** `sidepanel.html/.css/.js` uses the MV3 **Side Panel API**. It's opened from `background.js` via `chrome.sidePanel.open({windowId})` inside the action/command handler (must be a user gesture). The panel talks to the worker via `FLIPLENS_*` messages (`GET_HISTORY`, `RENAME`, `DELETE`, `CLEAR`, `OPEN`) and re-renders on the `FLIPLENS_HISTORY_UPDATED` broadcast.
- **Title + price scraping (non-obvious, brittle):** `results.js` is a declarative content script on `https://www.google.com/search*` and `https://lens.google.com/*`. It asks the worker `FLIPLENS_IS_PENDING` (matched by `sender.tab.id`); only if this tab is a FlipLens capture does it cache the `cid` and scrape. Prices come from a currency regex walked over text nodes, each mapped to its nearest ancestor `<a href>` so the low/high carry a source URL (Google `/url?q=` links are unwrapped); the title is best-effort (`og:title` → first `a h3` → heading → cleaned `document.title`) and user-editable. Expect to adjust heuristics when Google changes the results page.
- **Live re-search updates:** `results.js` keeps a `MutationObserver` + URL poll (throttled ~1.2s) so that dragging the Lens crop box (which re-searches) re-scrapes and re-reports for the same `cid`. `background.js` `handleResult` updates the existing entry and will NOT overwrite a title once the user has renamed it (`titleAuto === false`).
- **Google Lens hand-off (non-obvious):** Lens is invoked by a real `<form>` POST of `encoded_image` to `https://lens.google.com/v3/upload` from the uploader tab — a plain `fetch()` to Lens is blocked by Google, so it must be a form submit that navigates the tab. This is isolated in `uploader.js`; if Google changes the endpoint, fix it there (fallback: Google Images `searchbyimage/upload`).
- **Constraints:** the overlay only injects on `http(s)` pages (Chrome blocks `chrome://` and the Web Store). `captureVisibleTab` only grabs the visible viewport, so the item must be on-screen when selecting. The design is intentionally disk-free — do not add `chrome.downloads`.
- **Testing note:** end-to-end verification requires the Chrome GUI (load unpacked → capture → confirm a Google Lens results tab opens); there is no headless/automated test harness in this repo.
